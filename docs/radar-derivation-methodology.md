# 球队雷达图能力推导方法（Radar Derivation Methodology）

> 用途：从一支国家队的**球员名单 + 近期战绩 + 基础信息**，透明、可复算地推导出 8 维能力雷达图（进攻/防守/控球/状态/经验/定位球/球星/点球，均为 0–100 整数）。
>
> 本文件是**方法的权威来源**。实现里的 `deriveRadar()` 纯函数与本文件公式必须一致；为某队算雷达时以本文件为准。

---

## 1. 适用范围与所需输入

适用对象：拥有完整 `squad.json`（大名单）+ `recent_form.json`（近期战绩）+ `profile.json`（基础信息）的球队。

**所需数据字段：**

| 来源文件 | 用到的字段 |
|---------|-----------|
| `squad.json` | 每名球员的 `position`(GK/DF/MF/FW)、`value_wan_euros`(身价,万欧)、`caps`(国家队出场)、`goals`、`assists` |
| `recent_form.json` | 每场比赛 `result`(W/D/L)、`score`(如 "2–1")、`type`(friendly/qualifier/tournament)；仅计 `score` 不为 "-" 的已完赛 |
| `profile.json` | （预留）未来可加入 FIFA 排名等带级校准 |

---

## 2. 赛事权重规则

正式比赛比友谊赛更能反映真实实力（友谊赛对手常偏弱）。

| 赛事类型 `type` | 权重 |
|----------------|------|
| `qualifier`（预选赛） | **1.0** |
| `tournament`（世界杯等正赛） | **1.0** |
| `friendly`（友谊赛） | **0.5** |

> 默认正式赛 = 友谊赛的 2 倍。权重可整体调整，但改后需对所有已推导球队重算以保持刻度一致。
>
> 仅计入**已完赛**（`score` ≠ `"-"`）。

**加权聚合公式**（对已完赛集合）：

- 加权等效场次 `M = Σ type_weight`
- 加权进球 `GF* = Σ (本队进球 × type_weight)`
- 加权失球 `GA* = Σ (对手进球 × type_weight)`
- 加权积分 `Pts* = Σ (单场积分 × type_weight)`，胜=3 平=1 负=0
- 场均加权进球 `gf = GF* / M`；场均加权失球 `ga = GA* / M`
- 加权积分率 `pts% = Pts* / (3M)`

---

## 3. 身价锚点表（核心映射）

市场身价是数据中最客观的能力代理（Transfermarkt 综合市场共识）。把**某位置组的平均身价**（万欧）映射为 0–95 分：

| 位置组平均身价（万欧） | 分数 |
|----------------------|------|
| 0    | 35 |
| 1000 | 55 |
| 3000 | 75 |
| 5000 | 88 |
| 7000 | 95 |

记该分段线性函数为 `V(avg)`，钳制在 [35, 95]。位置组取值：
- `V_FW` = 前锋(FW) 组平均身价
- `V_MF` = 中场(MF) 组平均身价
- `V_DF` = 后卫(DF) 组平均身价
- （GK 不进入身价质量项；守门员能力由"场均失球"间接反映，见 §4 防守）

> 个人身价同样用 `V(单人身价)` 映射（如球星维度）。

---

## 4. 八维公式

每维输出 0–100 整数。`clamp(x, lo, hi)` 为钳制；`round()` 为四舍五入。

### 4.1 进攻 attack
```
attackForm = clamp( 分段(gf): (0→40)(1.0→60)(2.0→78)(3.0→92) , 40, 95 )
attack     = round( 0.65 * V_FW + 0.35 * attackForm )
```
依据：前锋阵容身价（主力信号）+ 加权场均进球（产出修正）。

### 4.2 防守 defense
```
defenseForm = clamp( 分段(ga, 反向): (0→92)(1.0→75)(2.0→58)(3.0→42) , 40, 95 )
defense     = round( 0.5 * V_DF + 0.5 * defenseForm )
```
依据：后卫阵容身价 + 加权场均失球（越少越高分；该项也吸收守门员表现）。

### 4.3 控球 control
```
mfGA        = MF 组每人平均 (goals + assists)
creativity  = clamp( 分段(mfGA): (0→0)(5→+4)(10→+8) , 0, 10 )
control     = round( clamp( V_MF + creativity , 35, 95 ) )
```
依据：中场身价 + 中场创造力（进球+助攻代理传控威胁）。

### 4.4 状态 status
```
status      = round( clamp( 分段(pts%): (0→35)(50→60)(67→80)(100→95) , 35, 95 ) )
```
依据：加权积分率（近期真实状态）。

### 4.5 经验 experience
```
avgCaps     = 全队平均 caps
experience  = round( clamp( 分段(avgCaps): (0→35)(20→55)(40→75)(60→88)(80→95) , 35, 95 ) )
```
依据：全队平均国家队出场数。度量定义=全队均值（含年轻替补，会拉低）；如需"主力经验"可改用 caps 最高的 11 人均值（见 §7）。

### 4.6 定位球 place_kick（代理指标，最弱）
```
squadGA     = 全队每人平均 (goals + assists)
base        = clamp( 分段(squadGA): (0→50)(8→70)(12→85)(16→92) , 40, 95 )
dfGoals     = 后卫组总进球
place_kick  = round( clamp( base + min(dfGoals, 12) / 6 , 40, 95 ) )
```
依据：全队得分产出门路 + 后卫头球（定位球争顶）代理。不确定性最高，标注提醒。

### 4.7 球星 superstar
```
maxVal      = 全队最高身价
vMax        = V(maxVal)              # 个人身价映射
eliteCnt    = 身价 ≥ 5000万 的球员数
eliteScore  = clamp( 分段(eliteCnt): (0→40)(3→65)(5→80)(8→95) , 40, 95 )
superstar   = round( 0.6 * vMax + 0.4 * eliteScore )
```
依据：头号球星身价 + 高身价球员数量。

### 4.8 点球 penalty（代理指标）
```
takerGoals  = 进球数最多球员的 goals
penalty     = round( clamp( 分段(takerGoals): (0→50)(20→70)(50→85)(80→92) , 40, 95 ) )
```
依据：主罚手（队内头号射手）的国家队进球数，代理其终结/点球能力。

## 5. 完整算例：巴西（2026-06-14 数据）

**位置组身价（万欧，来自 squad.json）：**
- FW(9人) 总 52700 → 均 5855.6 → `V_FW = 88 + (855.6/2000)*7 = 91.0`
- MF(6人) 总 19700 → 均 3283.3 → `V_MF = 75 + (283.3/2000)*13 = 76.8`
- DF(8人) 总 17850 → 均 2231.3 → `V_DF = 55 + (1231.3/2000)*20 = 67.3`

**加权战绩（14 场已完赛；3 场未赛世界杯排除）：**
- 正式赛(预选赛 6 场)：3W1D2L，进 7 失 6，积 10
- 友谊赛(8 场)：5W1D2L，进 22 失 10，积 16
- `M = 6*1.0 + 8*0.5 = 10.0`
- `gf = (7*1.0 + 22*0.5)/10 = 1.80`
- `ga = (6*1.0 + 10*0.5)/10 = 1.10`
- `pts% = (10*1.0 + 16*0.5)/(3*10) = 60.0%`

**逐维计算：**
| 维度 | 计算 | 结果 |
|------|------|------|
| 进攻 | 0.65×91.0 + 0.35×(60+0.8×18=74.4) = 59.15+26.04 | **85** |
| 防守 | 0.5×67.3 + 0.5×(75−0.1×17=73.3) = 33.65+36.65 | **70** |
| 控球 | 76.8 + creativity(mfGA=49/6=8.2→≈+6.5) = 83.3 | **83** |
| 状态 | pts%=60 → 60+0.588×20 = 71.8 | **72** |
| 经验 | avgCaps=916/26=35.2 → 55+0.762×20 = 70.2 | **70** |
| 定位球 | base(squadGA=268/26=10.3→78.6) + dfGoals(12)/6=2.0 = 80.6 → round | **81** (代理) |
| 球星 | 0.6×V(14000)=95 + 0.4×(elite=7→90) = 57+36 | **93** |
| 点球 | takerGoals=79(内马尔) → 85+0.967×7 = 91.8 | **92** (代理) |

**巴西推导雷达：`attack 85 / defense 70 / control 83 / status 72 / experience 70 / place_kick 81 / superstar 93 / penalty 92`**

## 6. 为新球队套用的步骤

1. 按本仓库 `squad.json` / `recent_form.json` / `profile.json` schema 录入该队数据（参照巴西）。
2. 调用 `deriveRadar(squad, form, profile)`（或手工按 §2–§4 计算）。
3. 把结果写入该队 `radar_data.json`（8 个整数）。
4. 在 PR/提交里附该队的 §5 式算例（位置组身价、加权战绩、逐维计算），便于复核。

## 7. 碰撞、精度与校准

**同分是否合理？** 雷达衡量**绝对能力**而非排名。两支进攻实力确实相近的队得到相同进攻分，是正确语义——雷达是能力轮廓，不是排行榜。两队靠其它维度形状与子分数区分。对 H2H 比赛模拟，绝对能力刻度才是对的模型（比的是绝对实力，不是相对排位）。

**要防的是"假碰撞"**——数据不同却被锚点/舍入压成同分：
- **留存子分数**：每维除最终整数分外，保留其原始输入（位置组均身价、加权 gf/ga、avgCaps 等），可下钻核对。
- **精度**：函数内部高精度计算；`radar_data.json` 存整数（与现有 47 队一致）；H2H 模拟若需可在内部用高精度。
- **形状区分**：8 维整体几乎不会完全重合。

**锚点重校准**：当累计推导 ≥ 5 支队时，检查分数分布是否合理（避免全挤 80–90 或两端堆积）；如不合理，整体调整 §3 身价锚点并对**所有已推导队重算**。

**刻度一致性提醒**：当前 47 支队的雷达为**手工设定**，与数据推导队**不在同一把尺子**。H2H 里推导队对手工队的横向比较需注意此差异。根治方式=逐步把所有队改用本方法推导。

**度量可选项**：`experience` 默认全队均值；如需反映"主力经验"，改用 caps 最高的 11 人均值（巴西会由 70 升至约 88）。切换度量属刻度变更，需对所有队统一并重算。

---

## 8. 已知局限

- **绝对刻度**：因各队大名单数据逐步才有，本方法用绝对锚点（非队间相对）。在多队推导并完成 §7 校准前，单队分数不依赖其它队。
- **代理维度**：`place_kick`、`penalty` 数据信号弱，公式为代理，不确定性最高。
- **小样本**：战绩维度依赖近 ~10–15 场，正式赛子样本可能很小（巴西仅 6 场预选赛），波动大。
- **身价时效**：身价随转会市场变动，需定期复核（巴西数据来源标注"Transfermarkt 需人工复核"）。
